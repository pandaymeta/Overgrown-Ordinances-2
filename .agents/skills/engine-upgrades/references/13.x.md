# 13.x — in-major breaking changes

Breaking `@gnsx/genesys.js` changes that shipped within the 13.x line, without a major version bump. Each section is labeled with the exact version that introduced it — apply a section only if the project's old version predates it.

## 1. Animation configs use serialized resources (introduced in 13.2.0)

`AnimationStateMachineComponent` no longer loads raw `*.anim.json` state-machine configs. Point `configUrl` at a serialized `*.animconfig.json` resource instead.

```ts
// Before (13.1)
const animationComponent = ENGINE.AnimationStateMachineComponent.create({
  configUrl: '@project/assets/character.anim.json',
});

// After (13.2)
const animationComponent = ENGINE.AnimationStateMachineComponent.create({
  configUrl: '@project/assets/character.animconfig.json',
});
```

Search the project for `.anim.json` references in scenes, prefabs, TypeScript, and serialized component data. Update each `configUrl` (and any other animation-config path fields) to the matching `.animconfig.json` path.

## 2. Migrate legacy configs and graph layout sidecars (introduced in 13.2.0)

Run the shipped migration utility in dry-run mode first:

```bash
node .agents/skills/engine-upgrades/scripts/migrate-animation-configs.mjs
```

Review every proposed conversion, blocked target, and reference update. Apply only when the dry run reports no blocked files or unresolved references:

```bash
node .agents/skills/engine-upgrades/scripts/migrate-animation-configs.mjs --write
```

The utility:

- recursively finds project-owned `*.anim.json` files while skipping generated, engine, dependency, and VCS directories;
- validates every config and sibling sidecar before changing any file;
- serializes each config with `AnimationConfigResource.fromConfig()` and `WorldSerializer.exportObject()`;
- embeds a sibling `*.anim.meta` graph layout into `graphEditorLayout` when present, supporting validated single-graph and v2 multi-graph sidecars;
- updates bounded `@project/...` and project-relative references, including Windows path forms and `.cjs`/`.cts` source files;
- blocks the entire write if any config, target, sidecar, or direct legacy reference cannot be migrated safely;
- writes resources and references before deleting old configs and migrated sidecars, rolling back pre-deletion write failures;
- resumes cleanup when an existing target exactly matches the resource the utility would generate.

If a sibling `*.animconfig.json` has different contents, a source file is invalid, a sidecar is malformed, or a direct legacy reference cannot be rewritten, the utility exits unsuccessfully without changing the project. Resolve every blocked item, then rerun the dry run.

For a single file outside the utility, convert with:

```ts
const resource = ENGINE.AnimationConfigResource.fromConfig(rawConfig);
const serialized = ENGINE.WorldSerializer.exportObject(resource);
```

## 3. Legacy animation config helpers removed (introduced in 13.2.0)

Replace imports of the removed legacy-format helpers:

```ts
// Before (13.1)
ENGINE.ANIMATION_CONFIG_LEGACY_EXTENSION;
ENGINE.isLegacyAnimationConfigPath(path);

// After (13.2)
ENGINE.ANIMATION_CONFIG_RESOURCE_EXTENSION;
ENGINE.isAnimationConfigResourcePath(path);
```

The replacement helpers describe the required `.animconfig.json` resource format; they do not detect or load legacy `.anim.json` files.

## 4. Virtual joystick `hidden` option removed (introduced in 13.3.6)

`VirtualJoystickOptions.hidden` (deprecated in favor of `enabled: false`) has been removed. Both meant exactly the same thing — skip creating the virtual joystick entirely — so this is a plain rename with no behavior change.

```ts
// Before (13.3.5)
const inputManager = new ENGINE.InputManager({
  world,
  virtualJoystickOptions: { hidden: true },
});

// After (13.3.6)
const inputManager = new ENGINE.InputManager({
  world,
  virtualJoystickOptions: { enabled: false },
});
```

Search the project for `hidden:` inside any `virtualJoystickOptions` (or per-stick `left`/`right`) object and replace it with the equivalent `enabled: false`. Drop `hidden: false` entirely instead of translating it — `enabled` already defaults to `'auto'`.

Reference implementations: `AnimationConfigResource.ts`, `AnimationStateMachineComponent.ts`, `migrate-animation-configs.mjs`, and `migrate-animation-configs-lib.mjs` in `.agents/skills/engine-upgrades/scripts/`; `InputManager.ts` for `VirtualJoystickOptions`.
